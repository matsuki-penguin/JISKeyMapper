# JISKeyMapper

キーボードの物理配列と Windows のキーボードレイアウトが一致しないときに、キー入力を正しい文字に変換する常駐ソフトです。

[English README](README.en.md)

---

## 概要

Windows は、接続された物理キーボードの配列に合わせてキー入力を補正しません。たとえば英語（US）配列に設定した Windows で JIS キーボードを使うと、`Shift+2` で `"` ではなく `@` が入力されます。JISKeyMapper はシステム全体のキー入力を横取りし、物理キーの刻印どおりの文字に変換します。

| モード | 用途 |
|---|---|
| **US_TO_JIS**（既定） | 英語配列の Windows で JIS キーボードを使う |
| **JIS_TO_US** | 日本語配列の Windows で英語キーボードを使う |

複数のキーボードを同時に接続している場合、変換するキーボードを選べます。たとえば「JIS キーボードだけ変換し、英語キーボードはそのまま使う」といった使い方ができます。

---

## 主な機能

- 記号キー、数字キーの Shift 入力、JIS 固有キー（変換・無変換・カタカナひらがな・ろ・¥）の変換
- 半角/全角キーによる IME のオン/オフ切り替え（英語配列の Windows 上で）
- キーボードごとの変換オン/オフ（トレイメニューの Device）
- 全体の有効/無効の切り替え（トレイアイコンの左クリック、またはメニューの Enable）
- IME と共存（文字コードの直接入力ではなく、仮想キーコードで入力を送出）
- Ctrl/Alt を含むショートカットは変換せずにそのまま通過
- Bluetooth キーボードをデバイス名で表示
- USB 機器を製品名と VID/PID で表示
- マウスやタブレットが持つキーボード機能を自動で除外。INI で任意の機器を手動除外することも可能
- リモートデスクトップ接続先での動作
- キーボードの接続・切断を自動検出
- 設定を `JISKeyMapper.ini` に自動保存
- Explorer の再起動後もトレイアイコンを自動で復元
- 多重起動の防止、高 DPI 対応（Per-Monitor V2）

---

## 動作環境

- Windows 10 以降（x64）
- 管理者権限（起動時に UAC の確認が表示されます）
- ビルドには Visual Studio 2019 または 2022 が必要

管理者権限で動くのは、管理者権限で動作しているアプリ（管理者として実行したコマンドプロンプトなど）でも変換を有効にするためです。

## ビルド

**x64 Native Tools Command Prompt for VS 2019/2022** を開いて、次を実行します。

```bat
cd C:\path\to\JISKeyMapper
nmake
```

| コマンド | 内容 |
|---|---|
| `nmake` | リリースビルド |
| `nmake DEBUG=1` | デバッグビルド |
| `nmake clean` | 生成物の削除 |
| `nmake rebuild` | clean してからビルド |

プロジェクトのルートに `JISKeyMapper.exe` が生成されます。DLL などの追加ファイルは不要です。

## 使い方

`JISKeyMapper.exe` を起動すると、タスクトレイにアイコンが表示されます。

### トレイアイコン

| 操作 | 動作 |
|---|---|
| 左クリック | Enable のオン/オフを切り替え |
| 右クリック | メニューを表示 |

アイコンの右下の色が状態を表します。

| 色 | 状態 |
|---|---|
| 緑 | Enable がオンで、Device に1台以上チェックがある（変換中） |
| 灰色 | Enable がオフ、または Device に1台もチェックがない（変換しない） |

アイコンにマウスを乗せると、`ON`、`OFF (disabled)`、`OFF (no device checked)` のいずれかで状態が表示されます。アイコンのラベル（JP/US）は現在のモードを表します。

### メニュー

| 項目 | 内容 |
|---|---|
| **Enable** | チェックを外すと、すべてのキーボードで変換を停止します |
| **Mode** | 変換モードを選択します |
| **Device** | 接続中のキーボードの一覧です。チェックしたキーボードだけ変換します |
| **Exit** | 終了します |

Mode の選択肢は次の2つです。

| メニュー項目 | 使う場面 |
|---|---|
| JIS keyboard on US-layout Windows | JIS キーボードを、英語配列に設定した Windows で使う（US_TO_JIS） |
| US keyboard on JIS-layout Windows | 英語キーボードを、日本語配列に設定した Windows で使う（JIS_TO_US） |

Device の名前は次の方法で表示されます。

- Bluetooth キーボード: デバイス名（例: `Keychron K1 Max`）
- USB キーボード: 機器が報告する製品名と VID/PID（例: `USB KEYBOARD  [VID_258A&PID_000C]`）
- リモートデスクトップ: `Remote Desktop keyboard`

新しく接続したキーボードは、最初はチェックが入った状態で追加されます。

JIS キーボードのキーを押したときに入力される文字です。表にないキー（英字など）はそのまま入力されます。

| JIS キー | 入力 | Shift+ |
|---|---|---|
| `2` | `2` | `"` |
| `6` | `6` | `&` |
| `7` | `7` | `'` |
| `8` | `8` | `(` |
| `9` | `9` | `)` |
| `0` | `0` | （入力なし） |
| `-` | `-` | `=` |
| `^` | `^` | `~` |
| `@` | `@` | `` ` `` |
| `[` | `[` | `{` |
| `;` | `;` | `+` |
| `:` | `:` | `*` |
| `]` | `]` | `}` |
| `\`（ろ） | `\` | `_` |
| `¥` | `\` | `\|` |
| 半角/全角 | IME オン/オフ | `~` |
| 変換 / 無変換 / カタカナひらがな | 各 IME 用キーとして送出 | 同左 |

## キー変換表（JIS_TO_US）

英語キーボードのキーを押したときに入力される文字です。刻印どおりの文字になります。表にないキー（英字、`1` `3` `4` `5` `,` `.` `/` など）は、両配列で同じ文字なのでそのまま入力されます。

| 英語キー | 入力 | Shift+ |
|---|---|---|
| `2` | `2` | `@` |
| `6` | `6` | `^` |
| `7` | `7` | `&` |
| `8` | `8` | `*` |
| `9` | `9` | `(` |
| `0` | `0` | `)` |
| `-` | `-` | `_` |
| `=` | `=` | `+` |
| `[` | `[` | `{` |
| `]` | `]` | `}` |
| `\` | `\` | `\|` |
| `;` | `;` | `:` |
| `'` | `'` | `"` |
| `` ` `` | `` ` `` | `~` |

IME のオン/オフは `` Alt+` `` で切り替えられます（英語配列の Windows と同じ操作）。`` ` `` キーは日本語配列では半角/全角キーの位置にあたり、Alt と組み合わせたときは変換せずにそのまま通すためです。

## 設定ファイル（JISKeyMapper.ini）

EXE と同じフォルダに自動で作成されます。通常はメニューから操作すれば十分ですが、`Exclude` だけは手で編集します。

```ini
[Settings]
Mode=US_TO_JIS
Enabled=1

[Devices]
Exclude=VID_2F24&PID_0135;VID_1234&PID_5678
Count=2
Path0=\\?\HID#VID_258A&PID_000C&MI_00#...
Check0=0
Path1=__RDP__
Check1=1
```

| セクション / キー | 内容 |
|---|---|
| `[Settings]` `Mode` | `US_TO_JIS` または `JIS_TO_US` |
| `[Settings]` `Enabled` | `1` = 有効、`0` = 無効 |
| `[Devices]` `Exclude` | Device メニューに出したくない機器。パスの一部（`VID_xxxx&PID_xxxx` など）をセミコロン区切りで指定します。大文字・小文字は区別しません |
| `[Devices]` `PathN` / `CheckN` | 各キーボードのパスとチェック状態。リモートデスクトップのキーボードは `__RDP__` として保存されます |

`Exclude` を変更したときは、JISKeyMapper を再起動してください。以前のバージョンで `[Settings]` に書いた `Exclude` は、起動時に `[Devices]` へ自動で移されます。現在接続していない機器の設定も消さずに残すので、Bluetooth キーボードを再接続してもチェック状態が保たれます。

## 技術的な仕組み

### 全体構成

JISKeyMapper は2つのスレッドで動作します。

| スレッド | 担当 |
|---|---|
| メインスレッド | トレイアイコン、メニュー、デバイスの列挙、INI の読み書き |
| フックスレッド | 低レベルキーボードフック（`WH_KEYBOARD_LL`）と Raw Input（`WM_INPUT`）の受信 |

低レベルフックは、一定時間（LowLevelHooksTimeout）内に処理を返さないと、Windows に黙って外されることがあります。デバイスの列挙（SetupDi API）やメニュー表示のような時間のかかる処理は、フックとは別のスレッドで行っています。両スレッドが共有するのはチェック済みデバイスのハンドル一覧だけで、SRW ロックで保護しています。この共有データは Devices.cpp の中に閉じ込めてあり、フックスレッド（Hook.cpp）からは `IsCheckedDevice` などの関数を通してしか参照しません。

### キーの横取りと送出

`WH_KEYBOARD_LL` フックですべての物理キー入力を受け取ります。変換対象のキーは元のイベントを破棄（`return 1`）し、代わりに `SendInput` で別の仮想キーコードを送出します。

- **仮想キーコードで送出:** 文字コード（`KEYEVENTF_UNICODE`）ではなく仮想キーコードで送るので、IME の変換中でも通常のキー入力として扱われます。
- **Shift の一時変更:** たとえば JIS の `Shift+7`（`'`）は、英語配列では Shift なしの `'` キーです。この場合は、押されている Shift（左右を個別に判定）を一時的に離し、キーを送った後に元へ戻します。逆に Shift を一時的に押す変換もあります。
- **自分の送出の無視:** `SendInput` で送ったイベントには `LLKHF_INJECTED` フラグが付くので、フックはそれを無視します。これにより変換の無限ループを防いでいます。
- **押下と解放の一致:** キーを押した時点の判断（変換する／通す／抑制する）をキーごとに記録し、離したときも必ず同じ扱いにします。押している間に Shift を離したり、Enable やモードを切り替えたりしても、キーが押しっぱなしにはなりません。
- **ショートカットの保護:** Ctrl または Alt が押されている間は変換しません。

### キーボードの判別

低レベルフックには「どのキーボードから来た入力か」の情報がありません。そこで Raw Input（`RegisterRawInputDevices` に `RIDEV_INPUTSINK` を指定）を併用し、`WM_INPUT` のデバイスハンドル（`hDevice`）でキーボードを判別します。

ここに一つ問題があります。`WM_INPUT` は、フックがイベントを通した後にしか生成されません。フックで破棄したキーには `WM_INPUT` が届かず、フックが判断する時点では、そのキー自身の送信元はまだ分かりません。JISKeyMapper は次の方法で送信元を推定しています。

1. **直前の入力から推定:** フックを通過したキーの `WM_INPUT` から、最後にキーを押したデバイスを記録します。通常は次のキーも同じキーボードから来ると判断します。
2. **押しっぱなしのキーで補正:** デバイスごとに押下中のキーを記録しています。最後にキーを押したデバイスではキーがすべて離されていて、別のデバイスで Shift などが押されたままなら、そちらを送信元とみなします。記録は判断のたびに `GetAsyncKeyState` で確認し、解放を取りこぼした古い記録は捨てます。
3. **半角/全角は解放時に判定:** 半角/全角キー（スキャンコード `0x29`）は、英語キーボードの `` ` `` キーと同じスキャンコードです。誤判定すると IME が意図せず切り替わるので、このキーだけは確実に判別します。
   - 押したときのイベントは破棄して保留します。
   - 離したときのイベントは通過させます。こうすると、そのキー自身の `WM_INPUT` が正しい `hDevice` 付きで届きます。
   - チェック済みのキーボードからなら、`VK_KANJI` を送出して IME を切り替えます。そうでなければ、保留していた `` ` `` を送出します。
   - 0.3 秒以内に `WM_INPUT` が届かない場合は、1. と 2. の推定で処理します。

### デバイスの列挙

- **一覧の取得:** `GetRawInputDeviceList` でキーボードを列挙します。
- **本物のキーボードの判定:** SetupDi API でキーボードクラス（`GUID_DEVCLASS_KEYBOARD`）に登録されているかを確認します。
- **マウスなどの除外:** マウス・タブレット・ゲームコントローラーなどが持つキーボード機能を、パス、デバイス名、HID の製品名（`HidD_GetProductString`）から判断して除外します。製品名に Mouse を含んでいても Keyboard も含むもの（キーボードとマウスのセット用レシーバーなど）は残します。
- **Bluetooth キーボード:** 1台のキーボードが複数の HID コレクションに分かれて見えるので、パス中の MAC アドレスで1項目にまとめます。デバイス名は `BTHLE\DEV_<MAC>` の登録情報から取得します。
- **リモートデスクトップ:** 仮想キーボードはパスが空になるので、`__RDP__` として1項目にまとめます。
- **接続・切断の検出:** `RIDEV_DEVNOTIFY` による `WM_INPUT_DEVICE_CHANGE` を受け取り、0.5 秒待ってから再列挙します。連続した通知をまとめるためです。

### 診断ログ

`src\Common.h` にある `#define JKM_LOG 0` を `1` にしてビルドすると、EXE と同じフォルダの `JISKeyMapper.log` に次の情報が記録されます。

- デバイスの列挙結果（採用・除外の理由、パス、キーボード情報）
- 半角/全角キーの判定経過

## 制限事項

### キーボードを切り替えた直後の1文字

次の条件がすべてそろうと、その1文字だけ変換されません。

- 英語キーボードで入力した直後である
- Shift などのキーを押していない
- 日本語キーボードで最初に押したのが変換対象のキー（`@` `[` `:` など）である

フックが判断する時点では、そのキー自身の送信元が分からないためです（「キーボードの判別」を参照）。Shift を押してから入力する場合や、英字キーから入力を始める場合は正しく変換されます。

### キーボードをまたいだ Shift

日本語キーボードの Shift を押したまま、英語キーボードの変換対象キーを押すと、日本語キーボードの入力と判定されて変換されます。

### 半角/全角キー

- IME の切り替えは、キーを離した時点で行われます。
- 英語キーボードの `` ` `` も、キーを離した時点で入力されます。押しっぱなしにしても連続入力されません。
- `Shift+半角/全角` は、IME の入力モード切り替えではなく `~` が入力されます。

### Ctrl/Alt を含むショートカット

Ctrl または Alt を含む入力は変換せずに通すので、JIS と US で仮想キーコードが異なるキーを使うショートカットは期待どおりに動かないことがあります。たとえば US_TO_JIS モードの `:` キーは `;` の仮想キーコードなので、VSCode の `Shift+Ctrl+:`（拡大）は `Shift+Ctrl+;` として届きます。

VSCode では `keybindings.json` に次を追加すると回避できます。

```json
{ "key": "ctrl+shift+oem_1", "command": "editor.action.fontZoomIn" },
{ "key": "ctrl+oem_minus",   "command": "editor.action.fontZoomOut" }
```

### リモートデスクトップ

リモートデスクトップの接続先では、手元のすべてのキーボードが1台の仮想キーボードとして届きます。接続先で動かす JISKeyMapper では、手元のキーボードを区別できません。

### 変換されない画面

UAC の確認画面やロック画面などのセキュアデスクトップでは、低レベルフックが呼ばれないので変換されません。

### JIS_TO_US モード

- CapsLock キーは、日本語配列の動作（英数キー。CapsLock は Shift+CapsLock）のままです。
- 日本語キーボードと英語キーボードを同時に使う場合、キーボードを切り替えた直後の日本語キーボードの半角/全角キーが、英語キーボードの `` ` `` と誤判定されることがあります。US_TO_JIS モードのような離した時点での判定は、このモードでは行っていません。
